### Parsing fragility
- Row terminator = `^|` literal + newline. Naive `read_csv` parses as 2 extra cols (`^`, autogenerated). DuckDB workaround: read w/ `delim='\|', quote=''`, drop trailing 2 cols. **Better:** preprocess `.dat` → strip `^|` before parse, OR write a custom reader.
- `.csv` files use plain `|`. `.dat` files use `|` + `^|` row marker. Two reader configs needed.
- Embedded-`|` risk in free-text fields untested. Could cause column-count drift. Worth verifying on `contracts.dat.parties` / `other_positional_interest`.

### CDBS / source-system
- `xref_cdbs_lm_app_id_transfer.dat` = **CDBS↔LMS app_id bridge**. CDBS pre-2013 records merged into LMS schema, not in separate dump.
- `lkp_filing_source` enum: `B` (batch), `I` (interactive web), `M` (manual web), `CDBS` (ETL'd), `L` (test). The `filing_source_code` column lives on `application.dat` or `license_filing.dat` — **unverified which**.
- Two app_id dialects in `ownership_interest`:
  - UUID format: `fa9043fc-fd1d-4217-89ae-4d23ccac2da1` (LMS-native)
  - Short-hash: `e8ee5645b4084e63abb9c1b6063ebeb7` (CDBS-translated, hypothesis)
- Schema implication: `app_id` is TEXT, two-dialect aware.

### Dupes (fragility-hit #9 — confirmed, worse than profile said)
```
1,217,754 total rows
  868,549 distinct (app_id, last_name, middle, suffix, title)
  349,205 dupes (28.7%)
  172,454 distinct application_ids → ~7 rows/app avg
```
- Top dupes: filings with hundreds of identical `(NULL, "NO FRN")` rows (worst = 247 rows on one app).
- Looks **intentional, not bug**: filer enumerated N placeholder parties below disclosure threshold.
- Schema impact: INV-#21 dedupe key `(applicationId, partyName, applicantFrn)` **over-collapses**. Must preserve `ownership_interest_id` PK (col 19) as actual row identity.

### "NO FRN" dominance (fragility-hit #8 — quantified)
```
419,460 rows = 34.4% of all ownership rows
```
- "NO FRN" is the **primary null mechanism**, not edge case. ~1 in 3 ownership rows.
- Zero empty strings, zero other text sentinels. Only NO FRN + real digit strings.
- 1 row has 8-digit FRN `00025044` — legacy short format. **FRN length validation can't assume 10 digits.**

### EEO demographics (new — not in OPIF)
Columns on `ownership_interest`: `african_american`, `american_indian_alaska_native`, `asian`, `ethnicity`, `gender`, `hawaiin_pacific_islander`, `white`, `tribal_nation_entity_ind`. FCC equal-employment-opportunity disclosure. **Policy decision deferred** — include / drop / aggregate?

### Name-change-under-stable-FRN (INV-#22) needs new source
- `frn_history.dat` is empty. The mechanism we expected to power INV-#22 doesn't exist in bulk.
- Candidates: diff `app_party.dat` rows across `apar_create_ts`, or external (CORES API). Unverified.
